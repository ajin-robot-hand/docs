    Dynamixel 제어 시스템 구축 및 안전 가이드¶

    이 문서는 Dynamixel 모터 기반의 다관절 하드웨어 시스템을 구축하고, 물리적 손상 없이 안전하게 소프트웨어로 제어하기 위한 프로덕션 레벨의 실무 가이드라인입니다.

    1. ⚠️ [중요] 하드웨어 안전 및 전원 관리¶

    1.1. 핫플러깅 엄금¶

    • 이슈: 전원이 켜진 상태에서 모터 케이블을 꽂거나 뽑으면 순간적인 서지(Surge) 전압이 발생하여 모터 내부 통신 칩(Transceiver)이 영구 손상됨.
    • 실행 수칙: 모터를 교체하거나 선을 연결/분리할 때는 반드시 U2D2 파워 허브 보드의 전원 스위치를 OFF로 전환할 것.

    1.2. 전력 병목(Current Bottleneck) 방지를 위한 분산 배선¶

    • 이슈: 7개의 모터를 하나의 라인(데이지 체인)으로만 길게 연결하면, 첫 번째 케이블이 7개 모터의 최대 부하 전류(최대 약 10A)를 모두 감당하게 되어 단선 및 셧다운 발생.
    • 실행 수칙: 허브 보드의 3핀 포트 2개를 활용하여 병렬로 분산 연결 (예: 포트A에 4개, 포트B에 3개). 소프트웨어 제어 시 논리적 순서에는 전혀 영향을 주지 않음.

    1.3. 유휴 상태 발열 통제 및 장치 보호¶

    • 이슈: 모터의 회전(Torque)을 끄더라도 통신 대기 상태 유지를 위해 제어 기판에 미열이 발생하며, 장시간 전원 인가 시 노이즈로 인한 칩셋 스트레스가 누적됨.
    • 실행 수칙: 코드를 실행하지 않는 디버깅 및 대기 시간에는 U2D2 파워 허브 보드의 전원 스위치를 즉시 OFF로 전환할 것.

    1.4. 외력 통제 및 백래시(Backlash) 방지¶

    • 이슈: 토크가 인가된 상태(모터가 위치를 유지하려는 상태)에서 기구부를 억지로 꺾으면 내부 엔지니어링 플라스틱/메탈 기어가 마모되어 영구적인 정밀도 하락 발생.
    • 실행 수칙: 모터가 힘을 주고 있을 때는 절대 물리적인 외력을 가하여 축을 회전시키지 말 것.

    1.5. 안전 종료(Graceful Shutdown) 패턴 보장¶

    • 이슈: 프로그램 강제 종료(Ctrl+C 등) 시 포트가 비정상적으로 닫히며 모터가 마지막 토크 상태를 무한히 유지해 과열을 유발함.
    • 실행 수칙: 제어 코드 레벨에서 반드시 SIGINT 시그널 핸들러를 구현해, 프로세스 종료 시 모든 모터의 토크를 0으로 해제하고 포트를 닫도록 아키텍처 구성.

    2. 하드웨어 물리 계층 규격¶

    2.1. 통신 인터페이스 매칭 룰¶

    하드웨어 구성의 기준은 항상 엔드 디바이스(모터) 스펙을 따라야 함.

    • XL430-W250-T 모델의 'T'는 3핀 TTL 통신을 의미.
    • 연결 원칙: 모터(3핀) ↔ 파워 허브 보드 TTL 포트(3핀) ↔ U2D2 TTL 포트(3핀)로 모든 데이터 경로를 통일해야 함.
    • 참고: 4핀 RS-485(차동 신호, 산업용) 및 4핀 UART(제어기-PC 디버깅용) 포트와 혼용 절대 불가.

    2.2. 데이지 체인(Daisy-Chain) 버스 토폴로지¶

    • 외형은 직렬로 보이나, 내부 회로는 3가닥(VDD, GND, DATA) 선을 공유하는 병렬 버스(Parallel Bus) 구조.
    • 모터의 물리적인 연결 순서는 통신에 무관하므로, 기구부의 관절 가동 범위 확보와 케이블 꼬임 방지에 유리한 동선으로 자유롭게 설계 가능.

    2.3. 전원과 통신의 물리적 분리 구조¶

    • 통신 모듈(U2D2)은 PC에서 5V를, 파워 허브는 SMPS 어댑터에서 12V를 독립적으로 공급받음.
    • 따라서 파워 허브의 물리적 스위치를 끄더라도 PC와의 시리얼 포트 세션(/dev/tty.* 또는 /dev/cu.*)은 끊어지지 않고 유지되므로 재연결 등 불필요한 컨텍스트 스위칭이 필요 없음.

    3. 소프트웨어 제어 아키텍처¶

    3.1. 위자드(Wizard 2.0)의 한계와 활용¶

    • Dynamixel Wizard 2.0은 단일 노드 진단 및 초기 설정용 유틸리티로 다관절 실시간 제어에 부적합함.
    • 스캔 병목 제거: 위자드 스캔 시 [Options]에서 ①타겟 포트 단일화, ②통신 속도(57600), ③Protocol 2.0, ④ID 범위(0~10)를 제한하여 탐색 시간을 초 단위로 최적화할 것.
    • 점유 해제: 설정 완료 후 반드시 'Disconnect(연결 끊기)'를 수행하여 OS 레벨의 포트 점유(Lock)를 해제해야 메인 제어 코드에서 에러가 발생하지 않음.

    3.2. Sync Write (동기화 쓰기) 아키텍처 도입¶

    • 7개 관절의 통신 지연(Delay)을 0에 가깝게 만들고 완벽히 동시에 구동하기 위한 필수 프로덕션 표준.
    • 동작 원리: SDK를 통해 7개 모터의 목표 위치 데이터를 메모리 상에서 하나의 거대한 패킷으로 조립한 뒤, 시리얼 버스 망에 단 1회만 브로드캐스팅(Broadcasting). 7개 모터가 이를 동시에 파싱하여 구동 시작.

    4. 프로덕션 레벨 제어 루틴¶

    소프트웨어 제어 로직과 하드웨어의 물리적 상태를 안전하게 동기화하는 5단계 워크플로우입니다.

    1. 물리적 전원 ON (부팅 딜레이 적용)
    2. 스위치 인가 후 7개 모터 내부 MCU 부팅(LED 깜빡임)이 끝날 때까지 통신 개시 전 약 1~2초의 대기 시간을 확보할 것.
    3. 포트 개방 및 초기화 (Fail-fast 패턴)
    4. 단순 포트 개방에 그치지 않고, 제어 시작 전 7개의 모터 ID에 Ping을 날려 정상 응답을 검증. 하나라도 누락 시 즉시 에러 반환 후 종료.
    5. 제어 및 테스트 (Sync Write 적용)
    6. 목표 위치 및 속도 명령 전송 시 통신 병목을 막기 위해 단일 패킷 브로드캐스팅 수행.
    7. 안전 종료 (인터럽트 처리)
    8. 제어 완료 또는 Ctrl+C 입력 시 시스템 셧다운 루틴이 개입하여 모든 모터의 토크를 해제(0).
    9. 물리적 전원 OFF
    10. 모터의 힘이 풀린 것을 물리적으로 확인한 후 파워 허브의 전원 차단.
