    3-Finger 로봇 손 — 파지(Grasping) 설계 중간 점검 및 Q&A 정리¶

    3-Finger 로봇 손의 파지(Grasping) 설계 과정에서 논의된 주요 기술적 질문과 방향성을 정리한 중간 점검 문서입니다. 프린트된 핑거팁 대신 XL430 액추에이터 평면 + 실리콘 테이프를 이용한 면 접촉 방식을 채택하였으며, 완전한 역학 유도 대신 경험적 검증(Empirical Characterization) 방식으로 개발을 진행합니다.

    배경 및 전제 조건

    • 접촉 방식: 프린트된 핑거팁 대신 XL430 액추에이터 평면 + 실리콘 테이프로 면 접촉 방식 채택.
    • 검증 방식: 완전한 역학 유도 대신 경험적 검증(Empirical Characterization) 방식으로 진행하기로 결정.

    1. 파지 난이도 — 200g 미만 물체 3종 비교¶

    대상 물체: 구(공), 물병(원통형), 수첩(얇은 직사각형)

    평평한 액추에이터 면과 얇은 실리콘 테이프 조건에서, 파지 난이도는 마찰력(힘) 관점과 위치 제어(정밀도) 관점에 따라 다르게 봐야 합니다.

    1.1. 구(공) — 마찰/형상 구속 관점에서 최난이도¶

    • 접촉 특성: 평면 패드가 곡면과 만나면 점/선 접촉만 가능하므로 접촉 면적이 작아 마찰력 의존도가 큽니다.
    • 실패 위험: 3개 손가락 대칭 배치로 기구적 중심은 잡히지만, 무게중심의 미세한 오차나 위치 오차로 인해 공이 굴러서 빠질 위험이 가장 큽니다.
    • 주의점: 그립 중심을 손 중심에 최대한 맞추어야 합니다. 형상 구속(물림) 없이 정적 마찰만으로 버텨야 하므로 그립 토크 안전마진을 가장 넉넉하게 잡아야 합니다.

    1.2. 물병(원통형) — 중간 난이도¶

    • 접촉 특성: 축 방향과 손가락이 평행하면 선 접촉이 형성되어 구보다 접촉 면적이 넓고 비교적 안정적입니다.
    • 실패 위험: 정렬이 어긋나면 선 접촉이 점 접촉으로 축소됩니다. 또한 내용물 액체의 쏠림에 따라 무게중심이 이동하는 변수가 있습니다.
    • 주의점: 표면 재질(매끄러운 플라스틱, 라벨 유무 등)에 따라 마찰계수 편차가 크므로 사전 실측이 필수적입니다.

    1.3. 수첩(얇은 직사각형) — 위치 제어 정밀도 관점에서 최난이도¶

    • 접촉 특성: 평면 대 평면 접촉이라 이상적으로는 접촉 면적이 최대가 되어 가장 안정적입니다.
    • 실패 위험: "정확히 정렬됐을 때만" 유효합니다. 조금만 기울어져도 패드 모서리만 닿는 점 접촉으로 전락합니다.
    • 주의점: 손가락 열림 폭 제어 정밀도가 부족하면 가장 먼저 실패할 수 있습니다. 두께가 얇을수록 허용 오차가 좁아지며, 페이지 눌림에 따른 변형도 변수입니다.

    1.4. 결론 및 시험 설계¶

    • 마찰/형상 구속 관점: 구(공)가 최난이도 → 그립 토크(힘) 테스트로 검증
    • 위치 제어 정밀도 관점: 수첩이 최난이도 → 정렬 정밀도 테스트로 검증
    • 두 실험의 목적이 다르므로 실험 설계를 명확히 분리하여 진행합니다.

    2. FastAPI 파지 프리셋 GUI — 방향성 검토¶

    웹 GUI로 파지 프리셋을 실행하고 모니터링하는 방향 자체는 타당합니다. 단, 제어 루프와 웹 서버의 구조 분리가 필수적입니다.

    2.1. 우려 지점¶

    FastAPI(비동기 웹 서버)가 모터 제어 루프까지 직접 담당하면, HTTP 요청/응답 오버헤드로 인해 타이밍이 불안정해질 수 있습니다. GroupSyncWrite 등 실시간성이 필요한 구간을 웹 요청 핸들러 안에서 직접 실행하는 것은 지양해야 합니다.

    2.2. 권장 구조¶

    레이어 역할
    제어 레이어 DYNAMIXEL SDK로 실제 모터 제어 (별도 프로세스/스레드). Mock PortHandler, bench calibration 코드 위치
    API 레이어 "프리셋 실행", "현재 상태 조회" 등 고수준 명령만 비동기로 처리
    • 큐(Queue) 통신: 두 레이어는 큐 또는 프로세스 간 통신(IPC)으로 연결합니다. 웹 요청이 몰려도 제어 루프 타이밍에는 영향을 주지 않습니다.
    • 모니터링: HTTP 폴링보다 WebSocket 스트리밍을 권장합니다 (FastAPI 기본 지원, 상태 실시간 푸시).
    • 안전장치: 타임아웃 및 부하 임계치 체크는 제어 레이어뿐 아니라 API 레이어에서도 우회 불가능하도록 설계합니다.

    3. 프리셋·모니터링 외에 중요한 것 (우선순위 순)¶

    1. 안전 정지(E-Stop) 메커니즘
    2. 소프트웨어든 물리 버튼이든, 예상 밖 동작 시 전 모터를 즉시 정지시키는(Torque Enable = 0) 경로가 필수적입니다. 데모와 테스트 중 장비 리스크를 최소화하는 핵심 요소입니다.
    3. 캘리브레이션 절차 문서화
    4. C0~C6 벤치 캘리브레이션 계획을 "전원 켤 때마다 몇 분 안에 영점 잡는" 표준 절차로 문서화하여 하드웨어 재현성을 확보합니다.
    5. 실패 로그 축적
    6. 실패 감지 로직이 감지만 하고 버리면 분석 자산이 되지 않습니다. 실패 유형(미끄러짐, 토크 초과 등), 물체 종류, 당시 부하값을 기록하여 "어떤 물체에서 몇 % 실패했다"는 정량적 근거를 확보하고, 향후 기대효과 및 평가 섹션 자료로 활용합니다.
    7. 케이블/배선 관리
    8. 손가락 반복 굴곡 구조 특성상 케이블 피로와 단선이 장기적인 리스크입니다. 설계 단계에서 케이블 여유 길이와 가동 경로를 충분히 고려해야 합니다.

    4. 프로젝트 목적 재정의 — 단순 데모에서 폐루프 검증으로¶

    4.1. 문제의식¶

    "물체를 든다"를 최종 목표로 두면 확장성이 약합니다. 파지 성공 자체는 데모로는 충분하지만 "왜 의미 있는 시스템인가"에 대한 답이 부족해집니다.

    4.2. 재구성 제안¶

    목적을 "저가 액추에이터(XL430)만으로 폐루프(closed-loop) 파지 제어가 가능한지 검증한다" 로 전환합니다.

    현재 구성 중인 요소들이 이미 폐루프의 핵심 역할을 담당하고 있습니다:

    폐루프 구성 요소 현재 보유 자산 세부 역할
    센싱 (Sensing) PresentLoad XL430 기반, PWM duty 역산 추정값 모니터링
    판단 (Decision) 파지 로직 프리셋 선택 또는 그립력 조정 판정
    구동 (Actuation) 모터 제어기 DYNAMIXEL SDK를 통한 실제 모터 제어
    기록 (Logging) 모니터링 데이터 실패 로그 및 시계열 부하 데이터 축적

    4.3. 확장 로드맵 (기획서 "기대 효과 및 활용 방안" 활용)¶

    • 1단계 (현재): 수동 프리셋 + 사후 모니터링
    • 2단계: 측정된 부하값 기반 자동 그립력 조정 (Adaptive Grasp)
    • 3단계: 물체 종류별 프리셋 자동 선택

    카메라나 복잡한 인지 센서 없이도 기존 로드/전류 데이터만으로 "적응형 그립"이라는 확장 스토리 구성이 가능합니다. "단순 데모"가 아니라 "검증된 1단계 + 명확한 확장 경로" 로 재구성하면 평가 관점에서 설득력이 크게 개선됩니다.

    5. XL430 부하 피드백의 한계와 실전 대응¶

    5.1. 문제 인식: Present Current 미지원¶

    경험자 조언에서 지적된 "액추에이터 해상도가 낮다"는 우려는 사실입니다. 스펙 확인 결과 XL430의 부하 피드백에는 구조적인 제약이 있습니다.

    • XL430 Present Load 스펙:
    • 범위: -1,000 ~ 1,000 (단위: 0.1%, 스톨 토크 대비 백분율)
    • 2000단계의 해상도로 수치 자체는 양호함.
    • 진짜 심각한 제약 — Present Current 미지원:
    • 상위 모델(XM430)에는 실제 전류를 mA 단위로 측정하는 Present Current 레지스터가 존재합니다.
    • XL430에는 이 레지스터가 없습니다. Present Load는 실제 전류 센싱이 아니라 내부 PWM duty cycle에서 역산한 추정값입니다.
    • 결과적으로:
      1. 실제 저항성 부하(그립력)와 관성/가속 부하가 섞여서 표시됩니다.
      2. 역기전력이 없는 저속·정지 상태에서 특히 부정확합니다 (파지는 대부분 정지 상태에서 유지됨).
      3. 온도, 전압, 모터 개체차에 따라 같은 그립력이라도 값이 다르게 나옵니다.

    결론: "PresentLoad > X 이상이면 안정적으로 잡았다"와 같은 절대 기준을 세우기는 어렵습니다.

    5.2. 채택 방안: 상대적 변화 감지 (변화량 기반)¶

    절대값 기준 대신 상대적 변화량 기반 감지로 전환합니다.

    • 기준선(Baseline) 기록: 그립 성공 직후의 안정된 PresentLoad 값을 기준선으로 기록합니다.
    • 미끄러짐 감지: 이후 이 기준선에서 값이 급격히 떨어지면 미끄러짐 신호로 해석합니다.
    • 이점: 상대적인 변화량만 비교하므로 개체차나 온도 드리프트의 영향을 훨씬 덜 받습니다.
    • 구현 팁: 10 ~ 20 샘플의 이동평균을 baseline으로 유지하고, 표준편차의 2~3배를 벗어나면 이벤트로 처리. XL430 노이즈 수준에서도 유효한 신호를 추출할 수 있습니다.

    5.3. 프로젝트 프레이밍에 미치는 영향¶

    이 한계는 오히려 프로젝트의 서사(Narrative) 를 명확하게 만드는 요소로 활용할 수 있습니다. 기획서/보고서에서 다음과 같이 프레이밍합니다:

    "저가 액추에이터(XL430)는 실제 전류 센싱을 제공하지 않아 절대적 힘 제어가 불가능하다. 본 프로젝트는 이 제약 하에서 상대적 부하 변화 감지 기반의 파지 유지 전략이 실용적으로 가능한지 검증한다."

    • 한계를 인정하는 동시에 그 한계 안에서의 해결 시도가 프로젝트의 정체성이 됩니다.
    • "왜 절대적 힘 제어를 안 했느냐"는 질문에 명확한 답변이 됩니다.
    • 확장 방향(3단계에서 핵심 관절만 XM430으로 부분 교체 → 실제 전류 기반 제어)과도 자연스럽게 연결됩니다.

    5.4. 확장 로드맵 재정리¶

    단계 내용 하드웨어
    1단계 (현재) 수동 프리셋 + 상대적 변화 감지 기반 유지 XL430 (전량)
    2단계 부하 변화 기반 자동 그립력 조정 (Adaptive Hold) XL430 (전량)
    3단계 (선택적 확장) 실제 전류 기반 정밀 힘 제어 그립 관절만 XM430 부분 교체
    4단계 (선택적 확장) 물체 종류별 프리셋 자동 선택 HW 추가 없이 SW로 가능

    5.5. 팀 논의 요약¶

    경험자 조언의 핵심은 "XL430의 부하 피드백은 참고용이지 제어용이 아니다" 라는 점입니다. 이를 명확히 인정하고 시작하는 것이 안전합니다.

    • 기본 방향: 절대값이 아닌 상대적 변화 감지로 진행

    이 문서는 팀 내부 논의를 위해 정리된 자료이며, 역학적 수치는 포함되어 있지 않습니다 (경험적 검증 방식 채택에 따름). 실측 데이터가 쌓이면 별도 표/그래프로 보강 예정입니다.
